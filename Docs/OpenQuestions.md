### Q-003 ✅ git push 인증
- 셸의 git(Git Credential Manager)에 GitHub 자격 증명이 없어서 `git push`가 실패함. Fork는 자체 계정을 사용하는 것으로 보임.
- **[임시 가정]** 커밋은 로컬에 계속 쌓고, 인증이 해결되면 한꺼번에 push한다.
- 사용자 답: Fork로 push하면 됨 → Claude는 Fork를 직접 조작할 수 없으므로 **커밋까지만** 하고 push는 Fork에서.
- 완전 자동 push를 원하면: 터미널에서 `git push` 한 번 실행해 GCM 로그인 → 이후 Claude가 직접 push 가능.

## Q-REWORK 인벤토리·상점·창고·몹 이동 재작업 (사용자 11-08, 임시 가정)
- 사용자: 기존 인벤토리·상점이 덧붙인 구조라 불편하고 일반적이지 않다. 처음부터 새로 만들고, 창고도 마우스 드래그·이동 편의 기능을 갖춰 일반 게임 수준으로. 몹 이동 로직도 어색해 수정. **다음 주** WSKILL-V2 와 함께.
- 임시 가정: ① 한 번에 갈아엎지 않고 데이터 모델→UI→입력→이행 단계로 새 구현하고 구 코드는 단계 통과 후 제거. ② 세이브(ES3) 기존 키 이름 변경 금지·마이그레이션 유지. ③ 기능 목록은 메이플식 최대(드래그&드롭·우클릭 사용·Shift 이동·정렬·일괄 판매·잠금·필터·창고 일괄 이동). ④ 몹 이동은 사용자가 지목한 이상 사례 먼저.
- 확인 필요(미정): 인벤 칸 수·탭 구조 유지 여부, 현재 불편 사례 목록, 창고 공유 범위, 몹 이상 사례(어떤 몹·상황).
- 범위 확대(사용자 11-08): 인벤·상점·창고·몹 이동에 한정하지 않고 **기존 모든 시스템**에서 '일반 게임과 달라서 유저가 힘든' 부분은 전부 수정(고유 설계는 제외). 큐 REWORK-0 에서 전수 점검 후 REWORK-1~3 로 진행. 임시 가정: 판단 기준 = 장르 관례(메이플·던파·디아)와의 차이로 유저가 처음에 예상 못 하는 동작.
- 전투 재설계 지시(사용자 11-08): 기존 설계를 전부 폐기해도 되니 던파·메이플처럼 일반 게임답게, 패드 편의 포함. 모든 무기가 공격 중 이동 가능하면 안 된다. 일부 무기는 던파처럼 앞키를 안 누르면 제자리에서 치고, 앞키를 누르면 공격하는 동안에만 살짝씩 앞으로 나간다. 큐 REWORK-4. 임시 가정: 이동 모드 3종(InPlace·LungeOnForward·Free)을 WeaponType 별 데이터로 지정, 전진 거리·속도는 설계서에서 정함. 확인 필요: 무기 타입별 모드 배정(예: 대검·창·도끼=제자리 계열, 단검·맨손=자유 계열)은 설계서 초안에서 제안.
- 퀘스트 통합 지시(사용자 11-08): NPC 퀘스트·퀘스트 보드·사냥꾼(의뢰 푯말) 퀘스트를 큰 시스템 하나로 합치고 정리. 큐 REWORK-5. 임시 가정: 퀘스트 데이터는 하나, NPC·보드·푯말은 같은 목록의 입구. 퀘스트 창(J) 한 곳에서 상태별 구분. 확인 필요: 보드 퀘스트와 NPC 퀘스트를 유형별로 계속 나눠 보여 줄지(탭), 사냥 의뢰(반복)와 스토리 퀘스트(1회) 구분 방식.
- 퀘스트 구조 지시(사용자 11-08): 메인 스토리 가이드 퀘스트·사이드 퀘스트(세계관 설명)·보상 획득용 퀘스트로 나누고, 클래식 메이플 퀘스트(스토리·내용·보상·경험치가 DB에 전체 존재)의 형태를 채용해 보상과 경험치를 주면서 세계관도 알게 한다. 큐 REWORK-6. 임시 가정: 구조·형식만 차용, 문장·고유명사는 새로 씀(저작권). 웹 조사는 Chrome/GPT 위임. 확인 필요: 퀘스트당 대사 분량, 메인 줄기의 층계별 분량, 사이드 사슬 수, 보상 비중(경험치·아이템·세계관 해금).
- 메이플 DB 참고(사용자 11-08): `https://mapledb.kr/` (메뉴: 아이템·몬스터·맵·NPC·퀘스트·월드맵). REWORK-6 조사 출처로 사용. 구조만 참고. 인게임 도감·정보 창(아이템·몬스터·맵·NPC·퀘스트 탭)의 구성 참고로도 쓸 수 있음.
- 레벨 디자인 참고(사용자 11-08): 메랜 DB 의 몬스터 데이터를 레벨 디자인·난이도 곡선 참고로 쓴다. 큐 REWORK-7. 임시 가정: 레벨 구간별 몹 스탯·경험치·맵당 몹 수를 표로 만들어 우리 곡선과 비교, 그대로 복사하지 않음.
- 초반 성장 구조 강화(사용자 11-08): 느낌은 나쁘지 않지만 더 튼튼하게. 퀘스트 등으로 반드시 새 무기를 얻게 하고 초반 30분(넓게 1시간)에 여러 경험을 하게 해 이탈을 막는다. 큐 REWORK-9. 임시 가정: 변화 간격 8~10분 이하, 중간에 퀘스트 확정 지급 무기 최소 1개(타입 다른 것), 첫 스킬·제작·강화·정예 경험을 1시간 안에 배치. 확인 필요: 초반 1시간 목표 레벨, 확정 지급 무기 종류.
- 맵 디자인 지시(사용자 11-08): 사냥·전투 느낌은 괜찮지만 맵 디자인이 이상함. 타일맵으로 맵을 다시 잘 찍고, 메랜 DB 맵을 참고. 큐 REWORK-10. 임시 가정: 구조(발판·로프·포털·스폰 분포)만 참고하고 이미지 복사 안 함, 시범 1장 후 사용자 검토 뒤 확장. 확인 필요: 이상하다고 느낀 맵·구체적 부분.
- 맵 컨셉 일치(사용자 11-08): 세계관(TO THE BEYOND)과 각 맵의 컨셉에 맞는 맵으로, 맵마다 잘 봐서 정리. 임시 가정: 맵별 컨셉 시트를 먼저 쓰고 현재 맵과 대조해 어긋난 맵부터 재작업(REWORK-10에 포함).
- 그래픽 분담 정정(사용자 11-08): 그래픽(타일맵 그림·배경·픽셀)은 PixelLab 방(모션·그래픽 생성)에서 하므로 Claude(총괄)는 그래픽 작업을 하지 않는다. 맵은 구조(발판·로프·포털·스폰·동선)와 컨셉 시트만 잡아 두고, 픽셀은 나중에 그쪽에서 채운다. REWORK-10 범위 축소.
- 맵·스폰 메이플 참조(사용자 11-08): 맵 구조와 몹 소환 방식이 메이플과 같으므로 메이플을 1순위 참조. 임시 가정: 맵당 스폰 지점·최대 몹 수·재생성 주기를 메이플 규칙에 맞춘다.
- 공용 트리 개정(사용자 11-08): 캐릭터 레벨 포인트로 강화(트리)창에서 전투/생활/편의성 3분류를 올린다(크리티컬 확률·방어도·최대 생명력·스태미나 등 포괄적인 것). 더블 점프·대시는 나중에 장비로 주고 트리에는 넣지 않는다. 무기 숙련 트리는 그 무기 종류 전용. `WeaponSkillProgression.md` V.3b 로 반영. 확인 필요: 생활 탭 노드 목록(채집·낚시·요리·제작 중 우선 순위), 편의성 노드 상한.
- 맵 점검 강조(사용자 11-08): 맵 점검 때 몹 배치 수량과 맵 생김새를 매우 중요하게 본다. 큐에 최상 우선 항목으로 등록(REWORK-10 핵심). 임시 가정: 맵별 표(크기·발판·로프·포털·스폰 수·최대 몹·재생성·밀도·사냥 효율)를 메이플 같은 레벨대와 비교.
