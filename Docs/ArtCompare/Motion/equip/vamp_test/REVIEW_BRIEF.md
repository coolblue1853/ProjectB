# 그래픽 방 검수 브리프 (11-13, 뱀파이어 걷기 시험 검수용)

이 문서는 장비 외형 그래픽 방이 11-10~11-13에 배운 것을 압축한 것이다. 검수자는 이 규칙과 기준으로 판정한다.

## 1. 역할과 말투
- 한글로만, 짧고 자연스러운 문장. 결과·결론부터. 되묻기·사과·인사 금지.
- 검수자는 읽기와 판정만 한다. 저장소 파일 수정·커밋·Unity 조작·PixelLab 생성 금지(검수 결과 문서 한 개만 지정된 폴더에 쓴다).

## 2. 사용자(작업 의뢰자)의 기준과 짜증 포인트
- 도트 게임은 외형이 가루처럼 흩어지거나 잘리면 안 된다. 자연스럽게 붙어야 한다.
- **큰 이미지를 훑어보고 "퀄리티 유지"라고 판정하면 안 된다.** 반드시 흰 바탕에 5배 이상 확대해 프레임별로 결함을 찾는다(이전에 이 실수로 신발 생성 결과를 합격 처리했다가 사용자가 확대해서 탈락시켰다).
- PixelLab 낭비 금지: 같은 시도 반복·의미 없는 시드 바꾸기·이미 실패로 결정된 방식 재시험 금지.
- 이미 결론 난 것을 다시 시험하지 않는다. 필요 없는 일은 하지 않는다.

## 3. 확정된 구조 결정 (11-10 밤)
- 외형은 **의상 하나(기본 움직임·몸 전체 외형 결정) + 무기(공격 움직임)**뿐이다. 모자·상의·하의·신발·장갑은 의상에 합친다. 나머지 슬롯(반지·목걸이·팔찌·귀걸이·허리띠·보조장비·마법석)은 외형 없는 능력치 슬롯이고 층계별 해금. 세트 효과는 조각 수가 늘수록 이펙트가 커지는 단계 연출.
- 상세: `Docs/Handoff/outfit_one_piece_decision.md`, `.claude-rules/Game/EquipSplitPlaybook.md`.
- 의상은 자체 모션 세트를 가질 수 있다(뱀파이어: 와인잔 대기, 둥둥 활공 이동). 이때 신발은 숨김 표시로 처리한다.

## 4. PixelLab 운용 지식
- 비용: edit_image_pro_flash 64px 5세대, animate_image_pixminimax 8프레임 1세대, transfer_outfit 약 10세대, inpaint 5세대. 호출 결과의 estimated_generations 를 합산해 상한을 지킨다.
- 로컬 이미지를 넘길 때 base64 는 잘린다 → get_upload_url 로 URL 을 받아 `curl -sS -F "file=@파일" URL` 로 올리고 반환된 `upload:<id>` 를 쓴다. 결과는 `https://api.pixellab.ai/mcp/images/<job_id>/download`.
- 의상 입히기: 속옷 프레임에서 edit(텍스트로 의상 지시)하면 포즈·머리·크기가 유지되고 옷이 잘 입혀진다.
- 모션: 옷만 있는 첫 프레임으로 pixminimax 를 돌리면 거의 안 움직인다. **첫 프레임이 이미 그 포즈(예: 잔을 든 손, 떠 있는 자세)여야 한다.** 그 첫 프레임을 edit(5세대)로 만들고 pixminimax(1세대)를 돌리면 와인잔 대기와 활공이 나온다. 루프는 처음·끝 실루엣 XOR 로 확인한다.
- 실패로 결정된 방식: (a) 신발 등 부위 영역만 마스크로 다시 그리는 inpaint(경계는 깨끗하나 모양이 프레임마다 뭉개지고 일관성 없음) (b) 완성 옷 그림을 색·영역 규칙으로 오려 부위 조각으로 쓰기(부스러기·끊김) (c) 팔레트 교체 시험은 색 표본 오염으로 무의미 (d) 새로 생성한 프레임을 기존 코트 포즈에 섞기(머리 최대 6px·발 최대 12px 어긋남).

## 5. 검수 판정 기준 (도트 품질)
각 프레임을 흰 바탕 5배 이상 확대해서 아래를 본다.
1. 루프: 첫·끝 프레임이 이어지는가, 프레임 사이에 점프가 없는가.
2. 일관성: 의상 모양·색·크기·윤곽이 모든 프레임에서 같은 옷인가(깃, 붉은 안감, 망토 길이).
3. 활공 느낌: 발이 떠 있고 망토가 뒤로 흐르는가. 걷는 동작처럼 보이면 감점.
4. 윤곽선: 깨끗한가, 떨어진 점 부스러기·구멍·번짐이 있는가. 프레임 번호와 위치(대략 좌표)로 적는다.
5. 얼굴·머리: 프레임마다 얼굴·머리카락이 달라지는가.
6. 사용 세대: 보고된 세대 합계가 상한 20 이내인가, 낭비(의미 없는 반복)가 있는가.

## 6. 검수 보고 형식
- 두 결과(sonnet, opus)를 각각: 합격/불합격, 결함 목록(프레임별), 쓴 세대, 한 줄 총평.
- 마지막에 둘을 비교한 결론 2~3줄(어느 쪽이 사용자가 쓸 수 있는 품질에 가까운가, 근거).
- 6줄 이내로 요약하되 결함 목록은 줄이지 않는다.
