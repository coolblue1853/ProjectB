# 슬롯 설계 판단: 5칸(모자·상의·장갑·바지·신발) vs 4칸(머리·갑옷 한 벌·장갑·신발)

## 결론 먼저
**외형 슬롯은 4칸(머리 · 갑옷 한 벌 · 장갑 · 신발)으로 줄이는 것을 권장한다.** 바지 칸과 장신구 칸은 능력치 전용(외형 없음)으로 두고, 장신구에 외형을 주려면 "완성 그림 위에 덧붙는 것"만 허용한다.

| 근거(같은 21프레임 · 같은 지표, `gen_exp1_reply/study4_slots.json`) | 5칸 | 4칸 |
|---|---|---|
| 조합 수(세트 2벌) | 32 | 16 |
| 분류 정확도 mIoU(M1h 지도, 시험 7장) | 0.801 | **0.856** |
| 상의/갑옷 IoU · 바지 IoU | 0.77 · 0.67 | 갑옷 **0.92** |
| 합성 1개당 구멍 · 노출 · 조각 | 0.2 · 9.3 · 0.5 | 0.2 · 9.3 · 0.5 (같음) |
| 합성 1개당 침범 | 4.0 | 3.8 |
| 상의↔바지 경계 침범(바지·자락 자리) | 344px(전체의 13%) | **0**(경계 자체가 없음) |
| 가려진 바지 문제(코트 자락 밑) | 단계 생성 또는 보완 층 필요 | **없음**(갑옷 한 벌 안에 들어 있음) |
| 세트 1벌 생성 | 한 번에 입히기 ~25~30 gen + 하의 단계 ~20 gen | **한 번에 입히기 ~25~30 gen만** |
| "바지면 딱 바지" | 자락 → 상의 정책이라 상의 레이어가 허벅지 바지 그림을 들고 다님 | 해당 없음 |

- 5칸에서 상의≠바지 조합(16개)과 상의=바지 조합(16개)의 결함 수는 거의 같았다. 결함은 **상의·바지를 나눠서가 아니라** 배낭 제거 자리, 머리 경계, 지도 오류에서 나온다.
- 즉 5칸은 결함을 줄여 주지 않으면서 생성 비용·도구·소속 정책 문제만 더한다. 상의·바지를 따로 섞는 재미를 포기할 만한 가치가 있다.

## 4칸에서 남은 결함 → 생성 없이 해결한 것(11-10 추가 연구, `gen_exp1_reply/study4_slots.json`, `code/study4_slots.py`)
| 4칸 구성(21프레임 × 16조합) | mIoU | 합성 1개당 구멍 · 노출 · 조각 | 전부 잎사귀일 때 머리 불일치 |
|---|---|---|---|
| 4칸(공용 지도로 자르기만) | 0.856 | 0.19 · 9.33 · 0.50 | 1,915 |
| + 세트별 모자 확장 + 모자 지울 마스크 | 0.856 | 0.19 · 8.00 · 0.52 | **635** |
| + 속옷 몸 목·턱 보정(`under_fixed/`) | 0.856 | 0.19 · **2.71** · 0.52 | **622** |

1. **머리 경계(남은 결함의 43%)는 해결 가능했다.**
   - 세트별 모자: 그 세트가 머리 구역에서 원본 머리와 다르게 그린 픽셀 중 모자 덩어리와 이어진 것을 모자에 더한다. 맨몸 자리는 어느 세트도 안 그리므로 다른 부위와 소속이 겹치지 않는다(구멍 증가 0).
   - 두건 잘림 1,621 → 478px. 남은 478은 전이가 얼굴을 다시 그린 잡음이라 일부러 뺀 것이다.
   - 지울 마스크: 모자를 쓰면 숨어야 하는 원본 머리카락(21프레임 합계 약 180~200px)을 모자 레이어의 `_erase.png`로 지운다. 런타임 `CelComposer`가 erase를 이미 지원하므로 C# 변경이 없다.
   - 내보내기: `export_runtime.py map ... --armor --cap-under under_fixed`.
2. **속옷 몸 목·턱 보정**: 남은 노출 전부가 맨몸 자리였다. 원인은 `under_base.py`의 머리 덮어쓰기가 목·턱 일부를 빠뜨린 것. 지도의 맨몸 자리 중 **머리 색 팔레트에 맞는 114px만** 원본으로 덮었다. 배낭·소매가 맨몸으로 잘못 분류된 86px은 건너뛰었다(덮으면 모든 옷에 박힘). 결과는 `result/under_fixed/`(21장, 기존 속옷 몸 대신 사용).
3. **뒷모습 들어 올린 손**(1차 failures, `ds_up_4` 장갑 IoU 0): 머리 구역 안 살색 덩어리 중 둘레 30% 이상이 옷(소품 제외)이고, 머리카락은 30% 미만이며, 얼굴에서 2칸 넘게 떨어진 것을 손으로 본다. up_4 0 → 10/13px, 다른 20프레임 변화 0. 전체 mIoU(5칸 기준) 0.792 → 0.801. `regions/` 21장을 이 버전으로 교체했다.

## 대머리 상태로 옷을 생성하는 안(사용자 제안 11-10)에 대한 판단
- **머리카락을 따로 떼는 것은 가능**하다(머리 구역 − 얼굴 살색 − 고글). 나중에 헤어스타일 교체를 원하면 이 방향으로 간다.
- 다만 **옷(특히 모자)을 대머리로 생성하는 것은 권하지 않는다.** 원본 머리숱은 고글 위로 2~5줄(평균 4줄, 19프레임 측정)이다. 대머리 두상에 맞춰 그린 모자는 그만큼 작고 낮게 앉는다. 머리카락 레이어를 모자 밑에 깔면 숱이 모자 위·옆으로 최대 4~5px 삐져나온다(64px 캐릭터의 머리 높이 약 25px 기준 큰 차이).
- 위 1번(세트별 모자 + 지울 마스크)으로 머리 불일치가 이미 1,915 → 622로 줄었으므로, **지금처럼 머리카락이 있는 상태로 한 번에 입혀 생성하는 것을 유지**한다.
- 확인하고 싶다면 1프레임만 대머리 + 모자로 생성해 보면 된다(약 10 gen, `GEN_RESEARCH_GUIDE.md` 실험 E).

## 배낭(사용자 결정 11-10: 기본 옷일 때만 보이는 꾸미기, 켜고 끄기, 다른 옷을 입으면 사라짐)
- 내보내기: `export_runtime.py map <원본 코트> regions base_coat <루트> --armor --split-back <패키지>`
  → `base_coat_top`(배낭 뺀 갑옷, 배낭 밑 몸 안쪽은 생성 0 보완) + `base_coat_backpack`(슬롯 `back`, 21프레임).
- 측정(21프레임): 배낭 픽셀 4,945. 그중 몸 안쪽 3,208px은 배낭을 끄면 속옷 몸이 드러나는 자리 → 보완으로 0px. 나머지 1,737px은 몸 밖이라 끄면 투명(정상). 확인 시트 `gen_exp1_reply/backpack_toggle.png`(켬 / 끔·보완 없음 / 끔·생성 0 보완).
- 품질: 옆·앞모습은 보완이 자연스럽다. **뒷모습 `ds_up_3·4`는 등판 전체가 지어낸 무늬** → 이 2프레임만 생성으로 메우는 것을 권장(GEN_RESEARCH_GUIDE 실험 B, 약 10 gen).
- 런타임: 슬롯 `back`이 C#에 없다. `CelEquipLayer.Slot`에 `back`을 추가하고 갑옷(body) 다음에 그린다. 그리는 조건은 `갑옷 = base_coat && 배낭 옵션 켬`. 이 조건 한 줄은 `CelEquipSync`에 들어가야 한다(C# 변경 필요, 작음).
- 다른 세트는 지금처럼 배낭을 버린다(`--back drop` 기본). 새 세트는 처음부터 배낭 없이 생성한다(실험 C).

## 장신구(배낭·망토·휘장 등) 외형을 줄 경우
- 장신구는 **위에 덧붙기만** 하면 분리가 쉽다. 갑옷 위에 그려지므로 가려진 부분이 생기지 않는다. 추출 = (갑옷 + 장신구로 생성한 그림) − (같은 갑옷 그림)의 차이. 반대 방향(장신구를 떼어 내기)은 장신구 밑 갑옷 그림이 없어 지금과 같은 구멍 문제가 생긴다.
- 그래서 규칙: **새 세트는 배낭·소품 없이 한 번에 입혀 생성**(GEN_RESEARCH_GUIDE 실험 C)하고, 장신구는 그 위에 따로 생성해 차이로 뽑는다.
- 기존 원본 코트는 배낭이 그림에 박혀 있으니, 배낭을 코트 갑옷의 일부로 둔다(지금과 같음).

## 기존 시스템에 미치는 영향
- 인벤토리 장비 칸(`CelEquipSync.ArmorBoxes`: 모자 2 · 갑옷 5 · 장갑 6 · 바지 8 · 신발 9)은 그대로 두고, **바지 칸(8)만 외형 레이어를 안 붙이면** 된다. `CelEquipMap.csv`에서 바지 아이템의 레이어 id를 비운다. C# 변경 없음.
- 레이어 내보내기: 지도에서 상의·바지·자락·배낭(2·4·8·7)을 갑옷(상의 슬롯 = body)으로 합친다. 지금 도구로는 `export_runtime.py map ... --hem top`에, 지도에서 4를 2로 바꾼 것을 넣으면 된다(바지 레이어는 빈 레이어로 나감). 4칸 전용 옵션 `--armor`를 추가하면 한 줄 작업이다.
- 1차·2차 연구의 바지 관련 결과(자락 소속 정책, 가려진 바지 보완·단계 A 생성, 하이브리드)는 4칸에서는 **필요 없어진다.** 5칸을 유지할 경우를 대비한 참고로만 남긴다.

## 확인하지 않은 것
- 4칸 수치는 지금 2세트(코트·잎사귀)와 원본 코트 기준 지도로 잰 것이다. 원피스·갑옷처럼 다른 실루엣은 아직 없다.
- 세트별 모자는 잎사귀 두건 1종으로만 확인했다. 투구처럼 머리를 거의 다 덮는 모자는 지울 마스크가 커지므로 따로 확인이 필요하다.
