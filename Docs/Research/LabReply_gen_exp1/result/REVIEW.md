## 2. 이번 정리에서 바뀐 것(지난 요약 대비)
- **`metrics.json`을 최신 지도·4칸 기준으로 새로 만들었다.** 1차 5칸 수치는 `archive/1st_study/report_1st.md`.
- **C# 대조로 버그 1건을 찾아 고쳤다.** `CelComposer`는 모자 지울 마스크를 모자 차례에 "지금까지 그린 그림 전체"에 적용한다. 그런데 지울 마스크 178px 중 5px가 갑옷·장갑·신발과 겹쳐 런타임에서 구멍이 될 뻔했다. 지울 마스크를 지도의 머리 영역(모자·맨몸 라벨)으로 제한했고, 평가기·점검기 합성도 C#과 똑같이 바꿨다. 수치 영향은 머리 불일치 621 → 622뿐이다.
- 시트를 4칸 기준으로 다시 만들었다(같은 8조합 × 6프레임: 구멍 80 → 32, 노출 1,621 → 220, 침범 393 → 364).
- 폐기된 5칸 산출물(하이브리드 바지, 단계 재절단, 5칸 보완 레이어, 옛 지도로 만든 안정화 지도, 옛 지시서)은 `archive/`로 옮겼다.
- 생성 지시서를 유효한 실험(A~E)만 남겨 새로 썼다. PixelLab 단가(Transfer Outfit (Pro) 64px = 15프레임/10 gen)는 공식 문서로 확인했다.
- 새 문제 발견: **4칸 경계의 프레임 간 깜빡임이 기준선의 2배**(98 → 213). 주로 신발·장갑 경계이고, 앞뒤 다수결로는 오히려 나빠진다(232). `failures.md` 1번.

## 3. 주의해서 볼 점
1. **침범은 개선되지 않았다**(3.2 → 3.3). 다른 지표는 좋아졌지만 섞어 입을 때 경계 픽셀이 다른 옷에서 오는 양은 그대로다.
2. **정답 라벨이 기준선 쪽으로 기울어 있다.** 8장을 기준선 지도 위에 손으로 고쳐 만들었다.
3. **노출 감소(8.0 → 2.7)의 일부는 정의상 줄어든 것이다.** 원본 픽셀을 속옷 몸에 복사하면 그 자리는 '원본과 같음'이 된다. 눈 확인은 5프레임 확대만 했다.
4. **옷은 2벌(코트·잎사귀)뿐이다.** M1h의 배낭 판정과 모든 채점이 같은 잎사귀를 쓴다. 원피스·판금 갑옷은 미확인.
5. **키 프레임 비율 33%는 4개 동작 21장에서만 잰 값이다.** 걷기·달리기 키 비율과, 키만 넣은 Transfer Outfit의 품질은 미확인(실험 A·D).
6. 모자 지울 마스크는 "세트 그림에서 머리카락이 없어진 자리"로 계산한다. 전이가 머리 픽셀을 실수로 빼먹으면 같이 지워진다.
7. 헤어 교체 규칙(모자 윗선 위만 지움)은 제안 단계다. 정밀도 0.84 · 재현율 0.54, 정수리 털은 모자를 쓰면 항상 지워진다.
8. 판정 못 한 실험: 메이플식 모자 앵커(비교 기준인 전이 그림이 흔들림), 대머리 생성 안(머리숱 두께 2~5줄만 측정).

## 4. 이대로 전달해도 되나
**지도·속옷 몸·내보내기 코드는 바로 넣어도 된다.**
- 형식: 기존과 같다. 점검 전부 통과(`README.md` 점검 절).
- 런타임: 4칸은 C# 변경 없이 된다. 바지 칸만 대응표에서 빼면 된다.
- 배낭 켜고 끄기를 쓸 때만 C# 3곳(enum `Back`, 빌더, `CelEquipSync` 조건)이 필요하다.

넣은 뒤 꼭 볼 것:
1. 인게임 대기·찌르기에서 **신발·장갑 경계 깜빡임**이 눈에 띄는지(수치상 기준선의 2배).
2. 잎사귀를 입었을 때 **배낭 자리 보완 무늬**, 특히 뒷모습이 거슬리는지.
3. 모자 지울 마스크로 **머리카락이 과하게 잘리는 프레임**이 없는지.

연구실에서 확인할 수 없었던 것: Unity 빌드·인게임 화면, 21장 외 동작(걷기 등)에서의 지도 품질(속옷 몸·원본이 없음).
