# 업무 생성·전달 규칙 (11-02) — 중복 작업 방지, 효율 최우선

## 0번 규칙: 사용자 지시 중계
- 사용자는 총괄(이 대화)하고만 말한다. 하위 세션은 사용자 지시를 모른다.
- 사용자가 준 지시·결정·루틴 중 **돌고 있는 세션의 작업에 영향이 있는 것만** 해당 세션에 `SendMessage`로 한 줄 중계한다(경로·핵심만). 영향 없으면 보내지 않는다 — 불필요한 전달은 그 세션의 토큰 손해다.
- 중계 전 자문: 이 세션이 이걸 모르면 틀린 일을 하거나 일을 두 번 하는가? 아니면 보내지 않는다.
- 새로 여는 세션은 브리프에 필요한 지시를 넣는다.

## 단일 원본
- 해야 할 일의 원본은 `Docs/Handoff/queue.md` 하나다. 세션을 만들기 전에 반드시 먼저 읽는다.
- 항목 형식: `- [ ] 내용 (담당: 세션이름, 파일: 건드릴 경로)`. 담당이 적힌 항목은 다른 세션이 가져가지 않는다.
- 새 일을 시작하는 세션은 항목에 `담당: 이름`을 먼저 적고 시작, 끝나면 `[x]`와 커밋 해시를 적는다.

## 세션 만들기 전 점검 (총괄)
1. `mcp__ccd_session_mgmt__list_sessions {"linked": true}` 로 이미 도는 세션 확인. 같은 주제·같은 파일이면 새로 만들지 말고 `SendMessage`로 그 세션에 추가 지시.
2. 큐에서 같은 항목이 있는지 확인(중복이면 합친다).
3. 같은 파일을 건드리는 세션은 동시에 두 개 열지 않는다. 겹치면 앞 세션이 끝난 뒤 시작.
4. 5줄 이내로 끝날 일은 세션을 만들지 않고 직접/scout.

## 전달 (총괄 책임, 사용자 요청 없어도)
- 산출물(계획서·규칙·큐 항목)이 생기면 총괄이 영향받는 **돌고 있는 세션**에 `SendMessage` 한 줄: "무엇이 어디에 생겼다 + 읽을 문서 경로 + 바뀐 점". 새로 여는 세션은 AGENTS.md 인덱스와 큐가 알린다.
- 전달은 사실만, 문서 내용을 복사해 보내지 않는다(경로만).
- 같은 내용을 두 번 보내지 않는다. 이미 보낸 것은 큐 항목 옆 `(전달됨: 세션이름)`으로 적는다.

## 세션 브리프 (만들 때)
- 목표, 읽을 문서 2~3개, 건드릴 파일, 끝났다는 기준, 보고 5줄. 저장소에 이미 있는 내용은 경로만 적는다.
- 끝난 세션은 결과를 큐·state.md에 남기고 닫는다. 다음 세션이 같은 걸 다시 조사하지 않게 결론을 문서에 적는다.

## 일일 총괄 교대 (11-03 사용자 확정)
총괄 세션은 매일 새로 판다. 보고·중계를 받는 세션이 길어지면 매 응답이 비싸지기 때문이다.
1. **전날 총괄 창에서** 사용자가 "오늘 시작"(+ 아침 질문 답변)을 말한다.
2. 전날 총괄은 ① 답변을 `Docs/OpenQuestions.md` 맨 아래 "[결정 MM-DD]" 절에 기록, ② 돌고 있는 하위 세션이 있으면 정리·종료 여부 확인, ③ `Docs/Handoff/state.md` 에 이월 사항 5줄, ④ `start_session`(fresh, `use_worktree:false`)으로 **오늘 총괄 세션**을 연다. 그 뒤 사용자는 새 총괄 창으로 옮긴다. 전날 총괄은 닫는다.
3. 오늘 총괄 브리프에 넣을 것: 규칙 문서 경로(`AutoRun.md`·`Dispatch.md`·`TokenEconomy.md`), 오늘 날짜의 누적 상한(AutoRun 표), 오늘 결정 절 경로, 큐·`state.md`·`MorningQuestions.md` 경로, 전날 하위 세션 이름과 상태, "하위 세션은 이 총괄이 `start_session`으로 연다. 알림이 이 총괄로 온다".
4. 하위 세션 알림은 세션을 만든 쪽(부모)에게 간다. 그래서 하위 세션은 **오늘 총괄이** 새로 만들어야 알림이 온다. 전날 하위 세션은 닫고 새로 시작한다(컨텍스트도 가벼워진다).
5. 저녁 종료 시 내일 질문 모음 작성(AutoRun 하루 종료 루틴)도 오늘 총괄이 한다.

## 세션 간 메시지 형식 (11-03 사용자 확정: 구조화 필드, 새 언어는 만들지 않음)
- **하위 → 총괄 보고**: 한 줄 필드 형식, 3줄 이내. 서술·재설명 금지.
  `상태=완료|진행|막힘 항목=<큐 ID> 커밋=<해시> 검증=<컴파일/테스트/플레이 결과> 미검증=<없음|항목> 사용량=5h<%>/주<%> 다음=<항목|대기|stop>`
  - 막힘이면 `막힘=<원인 한 줄> 필요=<총괄/사용자 결정>` 추가. 사용자 판단이 필요한 건 OpenQuestions 에 적고 `질문=<Q-ID>` 로만 알린다.
- **총괄 → 하위 지시**: 항목 ID·경로·바뀐 점만. 문서 내용 복사 금지. 예: `지시: 큐 INV-EXP 우선, 읽기=Game/InventoryRefactorDesign.md, 조건=통주 가득참 로그`.
- **보내지 않는 것**: "확인했음", "대기 중", 변화 없는 틱 알림. 변화(완료·막힘·질문)가 있을 때만 보낸다. 총괄도 이런 알림엔 응답하지 않는다.
- **사용자에게 가는 보고**는 읽기 쉬운 한글로 유지(1~2줄).
