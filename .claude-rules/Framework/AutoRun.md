# 자동 진행 운영 (11-02) — 5시간 한도 따라 멈췄다 재개, 주 6일 페이스

시작: 새 세션에서 `/loop` 뒤에 `Framework/AutoRun.md 의 틱 절차를 수행해` 입력(간격 생략 = 자기 페이스). 중지: 사용자가 말하거나 큐가 비면 stop.

## 기준 시각
- 주간 리셋 = 매주 월요일 13:00 KST (get_usage 의 Weekly `resetsAt`, UTC 04:00).
- 작업 창 = 리셋부터 6일(일요일 13:00 KST까지). 마지막 1일은 예비.

## 틱 절차 (깨어날 때마다)
1. `mcp__ccd_session_mgmt__get_usage` 로 5-hour %, Weekly %, 각 resetsAt 확인.
2. **5시간 한도**: 5-hour ≥ 90% 면 새 작업을 시작하지 않는다. 진행 중이던 작업은 `Docs/Handoff/state.md` 에 이어갈 지점 3줄 기록 후, `ScheduleWakeup` 을 5-hour `resetsAt` + 2분 뒤로 건다(최대 3600초 제한 → 남은 시간이 길면 3600초씩 연속으로).
3. **주간 페이스**: 허용치 = 작업 창 경과 비율 × 100%(리셋 직후 0, 6일 뒤 100). Weekly % > 허용치 + 8 이면 과속 → 허용치를 따라잡을 때까지 1800초씩 대기. 허용치 이하면 진행.
4. **진행**: `Docs/Handoff/queue.md` 맨 위 미완료 항목 1개를 꺼낸다. 담당 세션(`start_session`)으로 위임하거나 builder 에이전트에 맡긴다. 결과는 5줄 요약만 받는다.
5. 끝나면 queue.md 에 완료 표시 + state.md 갱신, 커밋. 곧바로 2번으로(한 틱에 작업 1개).
6. 큐가 비었거나 사용자 판단이 필요한 항목뿐이면 `stop`. 판단 필요는 `Docs/OpenQuestions.md` 에 쌓고 넘어간다.

## 금지·주의
- 사용자가 "플레이 중"이면 컴파일·플레이 정지 금지, 해당 틱은 건너뛰고 1200초 대기.
- 대기용 `ScheduleWakeup` 은 짧게(60~300초) 폴링하지 않는다. 한도 대기는 위 계산대로 길게.
- 한 작업이 5시간 창 안에 못 끝날 만하면(대형 빌드·장시간 캡처) 5-hour 70% 이상에서는 시작하지 않는다.
- 틱마다 보고하지 않는다. 사용자에게는 막혔을 때와 stop 때만 말한다.
- 실측 기록: 큰 작업 전후 5-hour %, Weekly % 를 `Docs/AutomationLog.md` 에 한 줄씩 남겨 1시간당 소모율을 갱신한다.
