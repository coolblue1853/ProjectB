# 장비 내구도·수리 (던파식) 도입 검토 (11-05) — 설계만, 코드 변경 없음

> 근거: 사용자 11-05 결정 1 — "나중에 장비 내구도·수리(던파식) 도입 여부 고민(설계만)". 사망 페널티는 현재 Lv1~10 EXP 손실 0, 그 외 5%(보스 7% 구간 제거) — `Docs/OpenQuestions.md` [결정 11-05].

## 1. 던파식 요약

- 장비마다 내구도(예: 100%). 전투(피격·사망)로 소모, 0 이 되면 **스탯 0 으로 취급(착용 효과 정지)**, 마을 NPC/수리 비용 지불로 회복. 사망 시 큰 폭 감소.
- 이 게임은 던파식 세트 파밍이므로 장르 일관성은 높다. 메이플에는 없다(대신 강화 파괴 등으로 싱크).

## 2. 장점 / 단점

| 장점 | 단점 |
|---|---|
| **골드 싱크**: 파밍 후반 골드 과잉을 지속 소모(가방 확장·제작 외 반복 싱크) | 초반 플레이어에게 "손해만 주는" 시스템 — 초반 소박·부담 최소 원칙과 충돌 |
| 사망 페널티를 EXP 외 수단으로 다양화(EXP 손실 0 구간 유지하면서 의미 있는 비용) | 사망 페널티·내구도 이중 부담 → 짜증/이탈(특히 보스전 반복 도전) |
| 장비 교체·예비 장비 보유 동기 | 장비 UI 복잡(툴팁·수리 UI·알림), 입력/패드 대응 |
| 세트 파밍 장기 목표와 궁합 | 세이브·밸런스·테스트 범위 증가 |

## 3. 소박 원칙 (도입한다면)

- **초반 면제**: 1층계(또는 Lv1~10) 장비는 내구도 소모 0(사망 EXP 0 구간과 동일 정책). 2층계부터 소모 시작.
- **0 이 되어도 파괴 없음**: 던파처럼 착용 효과 정지가 아니라, **스탯 50% 감소**처럼 완화(임시) — 완전 정지는 막힘 유발.
- 소모 원인은 **사망만**(피격마다 소모 금지). 사망 1회 = 장착 부위 전체 내구도 −5%(보스 −10%) 같은 소폭.
- 수리 비용 낮게: 아이템 가치 비례 소액 골드, 마을 NPC(대장장이/잡화) 일괄 수리 1클릭. 필드 수리 키트는 후속.
- 사망 배너 tips(11-05 결정)에 "수리하세요" 힌트와 낮은 내구도 경고 아이콘.

## 4. 골드 싱크 효과(추정, 임시 수치)

- 1층계 합계 가방 확장 2,500G 정도(`InventoryRefactorDesign.md` §7-3). 내구도가 2층계부터 사망 1회당 수십~수백 G 이면 골드 싱크가 사망 빈도에 비례(하드코어 플레이어에게 더 많이 소모).
- 사망이 적은 플레이어에겐 싱크가 거의 없어 **싱크로서는 불안정**. 안정 싱크가 필요하면 가방 확장·제작·강화·세트 재조합 비용 쪽이 낫다.

## 5. 사망 페널티와의 관계

- 현재: 사망 EXP 5%(Lv1~10 0). 내구도를 더하면 이중 페널티. **둘 다 약하게**, 합산 체감이 "다음 사냥 준비 비용" 수준에 머물게 한다.
- 대안: EXP 손실을 내구도로 **대체**(둘 중 하나만 활성) — 단순하지만 이미 확정된 사망 규칙을 다시 바꾸는 일이라 현재는 비추천.

## 6. 구현 크기 (도입 시)

| 작업 | 크기 |
|---|---|
| 순수 규칙 `DurabilityRules`(소모·수리비·효과 배율) + EditMode 테스트 | 소 |
| 장비 인스턴스 값 저장(`ItemStack` 에 내구도 필드 또는 병렬 배열 `inventoryFlags` 선례, ES3 추가만) | 중 |
| 스탯 합산에 배율 적용(`GameData`·장비 합산 경로) | 소~중 |
| 사망 처리 연동, 장비창/툴팁 내구도 표시 | 중 |
| 마을 수리 NPC UI(일괄 수리·비용 안내·패드) | 중 |
| 밸런스 CSV·PT-BOT 로그 | 소 |

총 **중상(약 5~6 큐 항목)**. 인벤토리 모델(`ItemStack`)·세이브·툴팁을 건드려 InventoryRefactor 계열과 충돌 가능.

## 7. 추천: **보류**

- 이유: 초반 소박 원칙과 충돌, 사망 규칙이 방금 확정된 직후, 구현 크기 중상, 골드 싱크는 다른 수단으로 이미 확보 중. 현재 최우선(1층계 완성·전투 조작감)에 비해 가치 낮음.
- 재검토 시점: 3~4층계 콘텐츠가 열려 골드 과잉이 PT-BOT 로그로 확인될 때. 그때는 §3 원칙(초반 면제·사망만 소모·파괴 없음)대로 **2층계 이후 한정 소박판**으로 도입.
- 지금 할 일: 장비 인스턴스에 나중에 필드를 붙일 수 있도록 `ItemStack` 신규 필드는 **ES3 추가만** 원칙 유지(`CodeStyle.md` §3). 별도 선행 작업 없음.
