# 마스터 모션 39 규격 (10-29 사용자 "규칙부터 다듬기")

근거: `MotionReferenceMaple.md`(메이플 34동작 실제 프레임), `MotionReferenceSurvey.md`(Mana Seed·Starbound·Terraria·Dead Cells 등 원칙 10), `MotionCoverage.md`(무기 247 × 직업 432 → 39개면 상한), `SkulReference.md`·`LimbusReference.md`(공격 문법·완급).
이 문서가 **동작을 만들 때의 기준**이다. 졸라맨 키는 이 표에서 시작한다. 10-29 생성분(기본·칼 3타 제외)은 이 규격으로 다시 만든다.

## 1. 공통 규칙

1. **분류 = 운동 방향 + 무기 끝 궤적.** 이름이 아니라 "무기 끝이 어디서 어디로 가는가"가 다르면 다른 동작, 같으면 같은 동작(무기·스킬이 달라도).
2. **키 포즈 3~5장을 먼저 정한다.** 준비(예비) → 타격 → 마무리(+ 회복). 키만 돌려도 무슨 공격인지 보여야 한다. 그다음 **키 사이에 사이 프레임 1장씩**(데드셀: 키 먼저 → 사이 나중) — 키 포즈만이면 보간 느낌이 안 산다(10-29 시험 사용자 판정). 완급은 유지 시간으로: 키 0.10~0.22초, 사이 0.05~0.06초, 타격 사이는 0.03초. 합계 8~10장.
3. **키 포즈는 크게.** 준비에서 무기 끝은 몸 실루엣 밖(머리 위·등 뒤·발 아래), 타격에서 몸 밖 앞쪽까지. 머리(골반) 이동은 준비↔타격 사이 **8px 이상**(10-29 실패분은 2~13px, 측정).
4. **무기 끝부터 정하고 몸이 따라온다.** 각 키 포즈마다 무기 끝 위치(셀 좌표)를 먼저 적고, 손·팔·몸통·다리를 맞춘다. 몸 방향과 무기 끝 방향, 이펙트 방향이 같아야 한다.
5. **양손 무기는 보조손 앵커 필수.** 셀 데이터에 주손·보조손 좌표를 같이 기록하고, 양손 무기는 두 손 사이를 지나도록 붙인다(10-29 대검이 한 손에 매달려 머리 뒤로 눕던 원인).
6. **프레임별 데이터:** 주손·보조손 좌표, 무기 각도(그림에서 읽은 값), 무기 앞/뒤 그리기 순서, 타격 프레임 번호.
7. **몸 중심 이동:** 베기 = 허리 비틀기, 찌르기 = 몸 전진, 내려찍기 = 상체 압축, 던지기 = 앞발 내딛기. 셀 안 골반 이동은 +5px 이내(나머지는 게임 물리).
8. **같은 몸 + 무기 프로파일 + 타이밍 프로파일**로 무기 차이를 낸다(3절). 몸을 무기마다 다시 그리지 않는다.
9. 얼굴은 가려도 되지만 **팔이 꺾이면 안 된다**(10-29 사용자).
10. 만들 때 3칸 비교: 메이플 해당 동작 · 스컬/림버스 해당 동작 · 우리 졸라맨. 레퍼런스 줄은 표의 "레퍼런스" 칸.

## 3. 무기 프로파일·타이밍 프로파일(몸을 다시 그리지 않고 무기 차이 내기)

- **무기 프로파일(무기 그림 json 에 추가):** 손잡이 피벗(있음), 각도 보정(°), 길이(px), **쥠 종류**(한손·양손·쌍수·세워 듦·몸 부속), 보조손 위치(손잡이에서 px — 양손 무기), 앞/뒤 순서 규칙, 이펙트 발생점(끝·총구).
- **타이밍 프로파일(무기군별):** 예비·타격·회복 배율, 히트스톱. 같은 A1 이라도 한손검 1.0 · 도끼 1.3 · 거대 둔기 2.0 처럼 구간별로 늘린다(전체 재생 속도만 바꾸지 않는다).
- 무기군 → 기본 타이밍(2절 완급이 1.0): 단검 0.7 · 한손검 1.0 · 창 1.1 · 양손검 1.2 · 둔기 1.4 · 활 1.0 · 총 0.6 · 지팡이 1.0 · 맨손 0.7 · 채찍 1.2.
