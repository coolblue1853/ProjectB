# 전투 입력 재설계 (REWORK-4, 11-11) — 공격 중 이동 모드·패드 입력·콤보/캔슬/선행

> 사용자(11-08): "결국 전투가 재밌어야." 던파·메이플처럼 일반 게임답게, 패드 편의 포함. **모든 무기가 공격 중 이동 가능하면 안 된다.** 일부 무기는 앞키를 안 누르면 제자리에서 치고, 앞키를 누르면 공격하는 동안에만 살짝씩 앞으로 나간다. 기존 구현은 폐기 허가.
> 이 문서는 **설계만**이다(코드 미작성, 수치는 전부 임시, 실플레이 미검증). `CombatFeelPlan.md`(CF-1~13, 구현 완료분)를 이 문서가 개정한다.
> **보존:** 모션 PNG·스미어 v7·타격 v7·기본 칼 3타(모션·판정 프리팹·후딜 길이). 이 문서는 타이밍·입력 규칙만 바꾼다. 원칙 `CombatSpec §9`(깊이축·긴 띄우기 금지)·`ClassicMapleDesign §6`은 유지한다.
> 읽은 코드(읽기만): `PlayerController.cs`(UpdateAttackRecoveryMove 280행, jumpBuffer 289·490행, 버퍼 상수 985~992행), `Weapon.cs`(29~37행 필드, 138행 `AttackMoveSpeedMul`, 427행 `CheckAttackWait`, 476~482행 캔슬 게이트), `AttackManager.cs`(`_attackBufferTime 0.2`, 154~244행), `CombatRules.cs`(31·87·104행 상수).

## 1. 현재 구조 진단

CF-1~10(`CombatFeelPlan §3`)은 코드에 다 들어 있다. 그런데도 "일반 게임답지 않다"는 이유는 구조에 있다.

| # | 항목 | 현재(코드) | 문제 |
|---|---|---|---|
| I1 | 이동 모드가 하나뿐 | 무기 프리팹 `isWeaponStopMove` 참/거짓 + `_driftMul 0.5`. 정지 무기는 **전부** 앞키 전진(`CanDriftNow`)이 켜진다. 거짓 무기(녹슨 검·RatCheifDagger·지팡이·아대)는 후딜 중 완전 자유(배율만 다름) | "제자리 무기"가 존재하지 않는다. 대검이든 단검이든 앞키만 누르면 미끄러진다 = 무게감·무기 정체성이 없다. 사용자 지시와 반대 |
| I2 | 전진이 연속 속도 배율 | `AttackMoveSpeedMul`이 후딜 내내 `moveSpeed×0.5`(마무리 ×0.25, 타격 전 ×0.7) 곱을 반환 | 던파의 "공격 한 번에 한 걸음" 보정이 아니라 **느린 걷기**다. 후딜이 1.0초인 대검은 5 u/s×1초 = 최대 5 u 미끄러진다 → 타격 위치 어긋남·몹 관통 |
| I3 | 전진 거리가 모션과 무관 | 후딜 길이에 비례해 거리가 늘어난다 | 후딜이 긴 무기일수록 오히려 많이 간다(역설). 거리는 **타 수·무기별 고정 값**이어야 예측 가능 |
| I4 | 입력 버퍼가 평타뿐 | 평타 0.2초, 점프 0.15초, 대시 0.1초, 스킬 별도 버퍼. **방향 입력 버퍼 없음** | 패드 스틱은 뗄 때 즉시 0으로 복귀 → 방향을 쥔 채 X를 누르려다 스틱이 중립에 돌아가 있으면 `FaceInputForAttack`·전진이 먼저 중립을 읽는다. 키보드보다 패드가 훨씬 자주 걸린다 |
| I5 | 점프 경로가 두 갈래 | 후딜 중: `UpdateAttackRecoveryMove`(290행, `CanJumpCancelNow`). 후딜 아님: 490행 `jumpBuffer.Peek && weaponStopMove == false` | 버퍼 소비 조건이 분산돼 있어 "판정 직후 점프 입력"이 누락될 수 있다(캔슬 게이트가 열리는 프레임에 버퍼가 이미 만료) |
| I6 | 캔슬 규칙이 후딜 비율 단일값 | 이동 캔슬 `_moveCancelFraction 0.4`(무기별 override 0건, 실측 `CF-12`), 마무리 +0.2 | 대검 후딜 1.0초면 0.4초 갇힌다. 단검 0.12초와 3배 차이는 있지만 **중량 무기도 캔슬이 너무 빠르다**는 반대 문제(무게감 없음) 공존 |
| I7 | 평타→평타 캔슬 없음 | 후딜 100% 끝나야 다음 타(선입력 0.2초는 소비 시점만 앞당김) | 가벼운 무기(단검·쌍검)는 연타 리듬이 느림. 던파는 후딜 중간 다음 타 가능 |
| I8 | 패드 홀드 연타 없음 | 평타는 `triggered`(눌림 에지)만. X를 쥐고 있어도 반복 안 됨 | 패드 엄지 피로(연타). 던파·메이플 모두 키 홀드 연속 공격 가능 |
| I9 | 공중 공격 | CF-6 `AirAttackVx`(관성 유지·입력 시 ×0.7) 구현됨 | 문제 없음. 유지(§3.5) |
| I10 | 패드 스틱 임계 | `MoveInput()`이 스틱 값을 직접 읽음(`DpadMoveRules`는 십자 옵션만). 앞키 판정 임계가 코드에 명시돼 있지 않음 | 약한 기울임(0.2)이 "앞키"로 판정되면 의도치 않은 전진. 임계·히스테리시스 필요 |

요약: **기반(캔슬 게이트·버퍼·방향 잠금)은 있으나 "무기마다 공격 중 이동 규칙이 다르다"와 "패드 입력 보정"이 없다.** 이 문서는 그 둘 + 콤보 선행 규칙을 정한다.

## 2. 기준 근거 (던파·메이플)

| 요소 | 던파(DNF) | 메이플 | 채택 |
|---|---|---|---|
| 공격 중 이동 | 공격 시작 후 방향키를 누르고 있으면 모션 동안 소폭 전진(기술 모션 자체에 이동 포함). 안 누르면 제자리. 무기·기술별 차이 큼 | 지상 공격 시 정지(후딜 짧음). 공중은 관성 유지 | **지상 = 무기 모드별(제자리 / 누르면 전진 / 자유), 공중 = 메이플(관성)** |
| 선입력 | 약 6~10프레임(60fps 기준 0.1~0.17초). 공격→공격·스킬 선입력 | 선입력 거의 없음, 대신 짧은 후딜 | 평타 12f(0.2초) 유지, 방향 5f 신규 |
| 캔슬 | 풍부(점프·대시·스킬·평타). 후딜 중간부터 | 공격 캔슬 거의 없음 | 점프·스킬·이동 캔슬은 현행, **가벼운 무기만 평타 캔슬** 추가 |
| 방향 | 공격 시작 순간 입력 방향으로 돌아섬, 모션 중 고정 | 공격 시작 방향 | 현행 유지(`FaceInputForAttack`) + 방향 버퍼 |
| 홀드 연타 | 공격 키 홀드로 콤보 연속 | 홀드 연속 공격 | 신규(I8). 패드·키보드 공통 |

수치(프레임·거리)는 한 작품의 공식 값이 아니라 **60fps 환산 일반 감각 임시 가정**이다(`Q-CI1~`).

## 3. 공격 중 이동 모드

### 3.1 정의 (`AttackMoveMode`)

| 모드 | 후딜·모션 중 앞키 | 뒤키·반대키 | 점프 | 의미 |
|---|---|---|---|---|
| `InPlace` | **무시**(제자리). 가로 속도 0 고정(MoveLock) | 판정 뒤 몸만 돌림(CF-5) 없음 — 모션 끝까지 방향 고정. 캔슬 창 이후에만 이동 | 판정+0.05초 이후 캔슬 가능(CF-2) | 무겁고 느린 무기·조준·시전 |
| `LungeOnForward` | 앞키를 **누르고 있는 동안만** 모션 시작 후 `LungeTime` 동안 고정 거리 `LungeDist`만큼 전진(§3.3). 놓으면 즉시 정지. 안 누르면 제자리 | InPlace와 동일(캔슬 창 이후 이동) | 동일 | 던파식 기본형. 근접 한손·연타 무기 |
| `Free` | 이동 가능(`MoveMulFree` 배율) | 가능(방향 전환도 허용: 모션은 유지) | 판정 이후 | 이동 시전. 원거리 평타 |

`isWeaponStopMove`는 `InPlace`·`LungeOnForward`에서 **참**, `Free`에서 **거짓**과 같은 의미로 취급한다(프리팹 값은 건드리지 않고, 모드 표가 우선).

### 3.3 LungeOnForward 동작 정의

시작 조건: 지상(`OnMovementGround`)·앞키(= 현재 바라보는 방향과 같은 방향 입력, §4.3의 방향 버퍼 포함)·모드 `LungeOnForward`·MoveLock 소유 중.

| 항목 | 값 | 설명 |
|---|---|---|
| `LungeTime` | `clamp(hitDelay + 0.12, 0.12, 0.30)`초 | 모션 시작(선딜 포함)부터. 타격 순간 직후까지만 전진 |
| 전진 속도 | `LungeDist / LungeTime` (u/s) | 거리가 후딜 길이와 무관(I3 해소). 예: 한손검 1타 0.9u / 0.19초 ≈ 4.7 u/s |
| 곡선 | 앞 60% 일정, 뒤 40% 선형 감속 | 급정지 방지 |
| 방향 | 공격 시작 시 정한 방향(`attackFacingLocked`). 입력이 반대로 바뀌면 전진 중단(뒤로 가지 않음) | |
| 해제 | 앞키를 떼면 즉시 0(남은 거리 취소). 재누름 시 같은 타에서는 재개하지 않음(`LungeTime` 소진 분 계속 차감) | 던파: 누른 동안만 이동 |
| 중단 | 몹 몸 판정과 접촉 / 벽 / 발판 끝(낙하 방지, 지상 한정) / 피격 | 몹을 밀고 가지 않는다(`ContactDamage` 무시 옵션과 별개) |
| 타 간 누적 | 없음. 타마다 새 `LungeDist` | 3타 콤보 총 전진 0.9+0.9+1.3 = 3.1u |
| 스태미나·달리기 | 달리기 입력은 무시(걷기 기준). 스태미나 소모 변화 없음 | 현행 `RunNow` 규칙 유지 |

`CombatRules`(순수)에 `LungeVelocity(mode, step, dist, elapsed, hitDelay, forwardHeld)` 추가로 EditMode 테스트한다.

### 3.4 후딜 이후 이동 캔슬 창(모드별 개정)

현재 `_moveCancelFraction` 0.4 단일값. 모드·무게별로 정한다. 캔슬 후 시작할 수 있는 건 이동·점프이며 스킬은 기존(50%·판정+0.05초).

| 구분 | 이동 캔슬 시작(후딜 비율) | 점프 캔슬 | 비고 |
|---|---|---|---|
| 경량(단검·쌍검·너클·채찍) | 0.30 | 판정+0.05초 | 연타 흐름 우선 |
| 표준(한손검·검방·낫·클로·창·도끼·철퇴·태도) | 0.40 | 판정+0.05초 | 현행 |
| 중량(대검·둔기·방패) | 0.55 | 판정+0.10초 | 무게감. 후딜 1.0초면 0.55초(현재 0.40) |
| 시전·조준(활·석궁·투창·마도서) | 0.50 | 판정+0.05초 | 발사 후 |
| Free(지팡이·아대) | 해당 없음 | 해당 없음 | 처음부터 자유 |

마무리 타(+0.2)·층계별 `CancelStartRatio(floor)`는 현행 유지(`WeaponCancelFraction`의 배율 구조 재사용). 이는 `CF-12`·`Q-CF12` 대검 0.55·단검 0.30 후보를 여기서 **확정**한다.

### 3.5 공중

공중 평타·공중 스킬은 모드 무관 `AirAttackVx`(관성 유지, 입력 시 ×0.7, 입력 없으면 0.15초 감속)를 유지한다. 단 `InPlace` 무기(대검 등)의 공중 공격은 입력 반영을 ×0.3으로 낮춘다(임시, Q-CI5).

## 4. 입력 규칙 (패드 최적화 포함)

### 4.1 버퍼 프레임 수 (60fps 환산)

| 입력 | 현재 | 제안 | 비고 |
|---|---|---|---|
| 평타 선입력 | 12f(0.2초) | 12f 유지 | 던파 6~10f보다 후하게. 후딜 말미 선입력 소비 보장 |

### 4.2 방향 입력 버퍼

- `DirectionBuffer`(순수 클래스, `InputBuffer` 형제): 매 프레임 `Record(h)`로 마지막 비영(非0) 방향과 시각을 저장한다. 질의 `Resolve(now, currentH)`는 `currentH != 0`이면 그것, 아니면 `now - lastTime <= 0.08초`인 마지막 방향을 돌려준다.
- 사용처 3곳: (1) 새 공격 시작 순간 `FaceInputForAttack`, (2) `LungeOnForward` 전진 입력 판정, (3) 반대키 방향 전환(CF-5)에서는 **쓰지 않는다**(실수 전환 방지).
- 근거: 패드 스틱은 손을 뗄 때 0.03~0.05초 안에 중립 복귀. 키보드는 키 업 직후도 눌림 상태가 거의 겹치지만 패드는 아니다.

### 4.3 스틱 임계

| 항목 | 값 | 설명 |
|---|---|---|
| 데드존(내) | 0.25 | 이하는 입력 0(이동·방향 모두) |
| 디지털 눌림 | 진입 0.5 / 해제 0.35 (히스테리시스) | 앞키 판정·Lunge·방향 전환·아래 점프(↓ -0.5)에 공통. 걷기 속도는 현행 아날로그 유지 |
| 약기울임 보호 | 0.25~0.5 구간은 걷기만, Lunge·방향 전환·캔슬 트리거 없음 | 의도치 않은 전진·캔슬 방지(I10) |

현재 `MoveInput()`(PlayerController 680행 부근)이 아날로그 값을 쓰는 부분은 그대로 두고, 새 `StickDigital`(순수 함수)을 Lunge·전환·캔슬 판정에만 쓴다.

### 4.4 점프 입력 일원화

- 점프 입력은 후딜 여부와 무관하게 **한 곳**(`TryConsumeJump()`)에서만 소비한다: ① 지상·코요테 유효 ② 후딜 아님 또는 `CanJumpCancelNow` 참. ②가 거짓이면 입력을 버퍼에 보존(0.15초).
- 490행 `weaponStopMove == false` 분기 조건을 위 함수로 대체한다(I5). 후딜 중 눌러 둔 점프가 게이트가 열리는 순간 나가게 한다(판정+0.05초가 입력 후 0.15초 안이면 성공).

REWORK-8(키 재배치) 진행 중이므로 버튼 배치(`InputAudit §5`)는 **바꾸지 않는다**. 보정만 한다.

- 녹슨 검 사용자 체감 값(걷기 3.0→1.8)은 Lunge로 대체되며 걷기 속도 배율 개념이 사라진다. 사용자가 "느리게 걷기" 감을 선호했다면 Q-CI2 참조.
- 방패 홀드 방어(`Hold the Line`)·활 차지는 자체 입력이므로 모드 표의 Lunge가 개입하지 않는다.
- `Docs/Playtest/InputAudit.md` 키 충돌표는 REWORK-8 builder가 갱신 중 → 이 문서는 버튼 배치를 바꾸지 않아 충돌 없음. 홀드 연타(X)·점프+공격(A+X)만 추가 규칙으로 등록.
- 히트스톱(`CF-11`)·몸박 약화(`CombatFeelPlan §7`)와 독립. 단 Lunge가 몹 접촉에서 멈추므로 몸박과 겹치는 빈도는 줄 것으로 예상(미검증).
