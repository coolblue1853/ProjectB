# 전투 조작감 개선 계획 (11-02, 코드 읽기 기반)

> 사용자(11-02): "전투 조작감이 아주 구리고 뻑뻑하다. 던파처럼 공격 중 앞키를 누르면 살살 앞으로 나가는 조작 편의가 다 빠져 있다." 이 문서는 진단·방향·구현 항목이다. 코드·Unity 작업은 하지 않았고, 수치는 전부 코드/프리팹 읽기로 얻었다(**실플레이 미검증**).
> 원칙 유지: `CombatSpec §9`(완전 횡스크롤, 깊이축·긴 띄우기 금지), `ClassicMapleDesign §6`(조작 유연함 층계별 개방). 기본 3타·스미어 v7·셀 주인공·모션/이펙트 리소스는 건드리지 않는다.

## 2. 클래식 메이플 vs 던파 — 선택

| 항목 | 클래식 메이플 | 던파 | 이 게임 |
|---|---|---|---|
| 공격 중 이동 | 지상 공격은 제자리(후딜 짧음), 공중 공격은 관성 유지, 점프로 공격 끊을 수 없음(스킬 모션 고정) | 공격 중에도 방향키 이동 가능(전진 보정), 캔슬 풍부 | 메이플 뷰이므로 **공중=메이플식 관성 유지, 지상=던파식 전진 보정** |
| 후딜 | 짧음(공속으로 해결) | 길지만 캔슬로 풀어줌 | 후딜을 줄이기보다 **캔슬 창**으로 풀어준다(무기 밸런스·모션 보존) |
| 점프 | 가변 높이 없음(고정), 공격 중 점프 가능 | 가변·백스텝 등 | 공격 중 점프 가능(메이플) + 가변 높이 |
| 대시 | 없음(스킬 이동) | 있음(공격 캔슬) | 층계별 개방(기존). 1층계는 대시 없이도 답답하지 않게 |

**결정: "메이플 뼈대 + 던파식 전진 보정(Attack Drift) + 짧은 캔슬 창" 조합.**
- 근거 1: 사용자가 던파식 전진 보정을 직접 요구했고, 이는 깊이축 없이 구현되는 가로축 보정이라 `CombatSpec §9` 원칙(깊이축 금지)과 충돌하지 않는다.
- 근거 2: 메이플 뷰 게임에서 지상 평타는 단순 제자리 연타로 끝나기 쉬운데, 전진 보정이 있으면 몹에 붙기·간격 벌리기가 쉬워 사냥 템포가 유지된다(`ClassicMapleDesign`의 사냥 위주).
- 근거 3: 캔슬은 새 모션 없이 코드(타이밍)만으로 추가되므로 기본 3타·스미어 v7 보존 원칙을 지킨다.
- **하지 않는 것:** 깊이축, 긴 공중 콤보, 평타로 띄우기, 후딜 단축(공속 경제와 얽힘), 벽 점프(별건).

## 4. 층계별 개방과의 관계 (`ClassicMapleDesign §6`)

- **1층계(클래식 감)**: CF-1(전진 보정, 약), CF-2(공격 중 점프는 판정 이후만), CF-4(버퍼·코요테), CF-5, CF-6, CF-8을 **처음부터 적용**한다. 이들은 "공격은 덜 답답하게" 원칙(§6 하단)에 해당하며 개방 조건으로 막지 않는다. 대시·2단 점프·활공은 기존대로 잠금.
- 전진 보정 세기는 층계가 올라도 올리지 않는다(무기·모션 타입에 따른 값). 대신 **CF-3 캔슬 창을 층계별로 앞당긴다**: 1층계 후딜 40%(CF-3 기본) → 3층계 30% → 5층계 20%. `MovementUnlockRules`와 같은 순수 판정 함수에 `CancelStartRatio(floor)`를 추가한다.
- CF-7(가변 점프)은 1층계부터 켜도 점프 높이 상한은 그대로라 "클래식 감"과 충돌하지 않는다. CF-9는 1층계에서도 켠다.
- 7층계 "현대 메이플 정도의 유연함"은 CF-13(평타 캔슬·이동 시전)으로 닫는다. 이번 계획은 1~3층계 범위.

## 5. 검증 방법 (Unity 사용 가능해질 때)

1. EditMode 순수 테스트: `CombatRules`에 `DriftSpeed(step, hasInput)`, `CanMoveCancel(elapsed, total, hitDelay, floor)`, `JumpCut` 판정 추가 후 `CombatRulesTests` 확장.
2. 플레이 프로브: 평타 연타 + →유지 이동 거리, 판정 전 점프 불가·판정 후 점프 가능, 점프 중 평타 수평 속도, 점프 키 단타/롱타 높이 비.
3. 스크린샷/연속 캡처: 3타 콤보 이동 영상(`Logs/playtest/`), 낮 시간대(`test-daytime` 메모리).
4. 회귀: 기존 `CombatRulesTests`·`InputBufferTests`, 녹슨 검 `_attackMoveSpeedMul 0.6` 동작이 CF-1로 대체될 때 속도 불변 확인(녹슨 검 걷기 3.0→1.8 사용자가 이미 본 값 유지: `driftMul` 1·2타 0.6으로 맞춘다).
5. 미검증이면 커밋 메시지에 "미검증" 표기.

## 6. 구현 순서(큐)

CF-1·CF-2·CF-3·CF-5(공격 이동 묶음, 같은 `Weapon.cs`·`PlayerController.cs`) → CF-4·CF-6·CF-7(이동 묶음) → CF-8·CF-9·CF-10. 같은 파일을 동시에 건드리지 않도록 **세션 하나로 순서대로** 진행한다. 상세 항목은 `Docs/Handoff/queue.md` 끝에 있다.

## 7. 몸박(접촉 피해) 비활성화/약화 검토 (사용자 11-03: 피격 경직은 유지, 몸박이 요즘 게임에 안 어울리면 비활성화도 검토)

현재: `ContactDamage`(0.1초마다 겹침 검사, 무적 아니면 1회 피해 + 약한 넉백/경직 + 짧은 무적). 일반 몹 최대 HP 6~10%, 정예·보스 12~18%(`ClassicMapleDesign §3.3`). 클래식 메이플의 핵심 긴장 요소다.

| 안 | 장점 | 단점 |
|---|---|---|
| A. 유지 | 클래식 감·"윗지역 가면 죽는다" 압박 유지, 구현 변경 없음 | 근접 전진 보정(CF-1)으로 몹에 붙기 쉬워져 몸박을 더 자주 맞음, 요즘 감각엔 불쾌 |
| B. 약화(권장) | 층계별로 조절 가능, 클래식 감 유지 | 수치 조정 필요 |
| C. 완전 비활성화 | 조작감·공격 접근 편함, 공격 판정 있는 몹만 위협 | 몹 위험이 약해져 레벨 구간·사망 페널티 설계(`Floor1Completion`)와 어긋남, 물약 소비 감소 |

**권장: B — 1층계부터 약화하고 층계 상승 시 복원.** 구체:
- 일반 몹 몸박 피해 ×0.5(최대 HP 3~5%), 정예·보스는 유지. 몸박 후 무적을 짧게 유지하되 넉백 거리는 감소.
- **공격 모션 중(플레이어 후딜 중) 몸박 무시** 옵션: 몹에게 붙어 치는 동안 맞지 않게 하는 것이 전진 보정과 어울린다. 슈퍼아머 몹·보스는 제외.
- 구현: `ContactDamage` 에 `Mul(floor, isElite)` 순수 함수와 `AttackingGrace` 판정 추가, `CombatRulesTests` 확장. 설정 필드 `contactEnabled`(전역 비활성화 스위치)도 두어 C안이 필요하면 값만 바꾸게 한다.
- 검증: 1층계 숲에서 몹 앞 평타 연타 시 피해량·횟수 측정, 물약 소비 시간 비교(`Floor1Balance`). 사망 페널티·레벨 구간 영향 확인.
- 판단은 사용자 몫: Q-CF3로 `Docs/OpenQuestions.md`에 임시 가정(B안) 기록.

## 9. 선정 항목: CF-11 잔여분 — 적 히트스톱 강화 (AUTO-113, 11-05 확정, 코드 읽기만·미구현)

CF-11 의 "적 스프라이트 정지"는 이미 코드에 있다: `HitFeedback.OnEnemyHit` → `SpriteHitFx.HitStop(sec)`(Animator.speed 0, 타이머 후 복원, `max` 갱신으로 누적 없음, 전역 timeScale 미사용). 현재 적 정지 `StopBasic 0.06`·`StopSkill 0.06`·치명 `+0.03`, 처치 시 적 정지 없음(디졸브 진행). 공격자 정지는 별도(`BasicStop()` 0.05, 마무리 0.08). 따라서 남은 비그래픽 델타는 **수치 미세 상향 + 마무리 타 구분** 하나다(렌더러 애니 정지만, 그래픽 산출물 없음).

- 파일: `Assets/Script/Combat/Feedback/HitFeedback.cs` 1개만(`SpriteHitFx.cs`·`PlayerController.cs` 수정 없음).
- 변경:
  - `StopBasic` 0.06 → **0.07**, `StopSkill` 0.06 → **0.07**, 치명 보너스 `StopCritBonus` 0.03 유지.
  - 신규 `const float StopFinisher = 0.10f`. `OnEnemyHit` 의 `stop` 계산에서 `!isSkill && IsFinisher()` 이면 `StopBasic` 대신 `StopFinisher` 사용(치명 보너스는 그대로 더함). 기존 `IsFinisher()` 재사용.
  - 처치(`killed`) 분기·공격자 히트스톱·흔들림 티어·플래시 수치는 건드리지 않는다.
- 영향 줄: `HitFeedback.cs` 20행(상수)·51~54행(`stop` 계산). 정지 상한: `0.10 + 0.03 = 0.13s` 이하(깜빡임 느낌 방지, 클램프 불필요).

  3. 컴파일 0, 기존 EditMode(`CombatRulesTests` 등) 통과. 플레이 연속 캡처는 선택.
